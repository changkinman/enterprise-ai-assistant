# EchoMind 量化评测报告

评测日期：2026-09-07。所有案例和知识文档均为匿名化、自建的合成企业服务材料；
本报告以第二轮扩展集结果为准，结果用于开发阶段的回归基线，不等同于线上真实员工流量表现。

## 可用于简历的核心数据

| 模块 | 测试材料与口径 | 结果 |
| --- | --- | --- |
| 意图识别 | 300 条、10 类企业服务意图，每类 27～37 条；LLM + Pattern（当前第三方 Anthropic 兼容配置下 Embedding 分支自动关闭） | Accuracy **92.33%**，Macro-F1 **0.922**；P50/P95 为 **884ms / 2.05s** |
| RAG 检索 | 20 篇匿名化制度文档、100 条问题；原始向量检索对比“查询改写 + 并行召回 + 去重 + LLM 重排” | Recall@1 **29.0% → 80.0%**（+51.0pp）；Recall@3 **51.0% → 85.0%**；MRR **0.430 → 0.825**；nDCG@5 **0.492 → 0.832** |
| RAG 延迟 | 同一 100 条问题，容器化 ChromaDB | 增强链路 P50/P95 **2.13s / 2.93s**；原始向量检索 **48ms / 227ms**。相关性提升伴随 LLM 调用延迟，需要按场景权衡 |
| 三级记忆 | 60 个场景：工作记忆 20、跨会话情景记忆 20、摘要压缩 11、隔离 4、画像 3、负例 2 | 工作/情景/画像事实召回均为 **100%**；摘要后关键事实召回 **97.26%**，摘要输入上下文平均缩短 **17.84%**；用户隔离 **4/4 通过** |
| RAG 依据回答 | 从同一 RAG 集隔条抽取 50 问题，覆盖 20 篇文档；回答仅使用增强检索证据 | 标准要点覆盖率 **73.68%**；LLM-as-Judge 平均分 **0.919**、通过率 **86%**。Judge 与回答模型同源，仅作为开发信号，不建议单独作为简历数字 |

## 当前已修正的问题

- 统一了意图语义：财务/报销优先归入 `billing`；技术类查询和请求归入 `technical`；`query`、`request` 仅保留通用服务场景。
- 为 LLM 重排增加了空索引列表回退，避免异常模型输出清空已有召回结果；已有回归单测覆盖。
- 用户画像增加部门、办公地点、常用业务等长期实体；画像以可读 UTF-8 注入上下文。
- 摘要改为带关键实体保留约束的紧凑提示词。

## 不应写入简历的数字与后续改进

- 实体抽取仅有 8 条标注样本，即便当前微平均 F1 为 0.933，也不具备简历统计意义。
- 记忆负例（无关问题不应带出历史）为 **0/2 通过**：用户间过滤正常，但同一用户的相似却无关历史仍会被 Chroma 返回。应增加相关性阈值或二阶段相关性判别后再主张“无关历史抑制”。
- RAG 回答质量的 Judge 与回答使用同一模型，存在自评偏差。下一轮应增加独立模型或至少 30 条人工盲审校准。
- 意图集仍是自建合成集。下一轮建议由不同人员标注，并在原生 Embedding 配置下补跑三路融合结果。

## 推荐简历表述

> 设计企业内部智能服务助手：以 LLM Few-shot、规则与 Embedding 组成可配置意图识别，并结合 Redis + ChromaDB 三级记忆和 RAG 多路检索。基于 300 条匿名化意图集实现 92.33% Accuracy / 0.922 Macro-F1；在 20 篇制度文档、100 条查询的离线集上，通过查询改写、并行召回、去重与 LLM 重排将 Recall@1 从 29.0% 提升至 80.0%、MRR 从 0.430 提升至 0.825；搭建 LLM-as-Judge、Prometheus 指标与回归评测闭环。

如需更保守的表述，可将“提升至”替换为“离线评测达到”，并保留“匿名化自建测试集”的说明。
