# 采购申请与供应商管理规范

> 版本：V1.0｜适用对象：提出采购需求、选择供应商或参与验收的员工。

## 1. 目的

在实际工作中，本节内容应作为后续流程的判断基础。员工遇到新情况时，先确认目标、事实和影响，再选择对应的处理方式；管理者应确保相关说明能够被员工找到、理解并执行。

采购需求应能够被没有背景的审核人理解，不能只写品牌、型号或供应商名称。说明业务问题、使用场景和验收结果，才能判断采购是否必要以及报价是否可比。

采购管理的目标是让业务需求、预算、供应商选择、合同、交付和付款形成完整链路。采购不是简单比价，而是要在质量、成本、服务、信息安全、合规和长期使用风险之间做出可解释的选择。

确保采购需求真实、预算明确、供应商选择公平、合同和交付可追溯，降低质量、成本、合规和信息安全风险。

## 2. 采购流程

具体适用时，应结合岗位、业务场景和风险程度判断，不宜只看表面形式。规则发生变化或现有说明无法覆盖时，及时向指定负责人确认，并把已经确认的处理方式记录下来，避免不同人员重复猜测。

供应商评估要把短期价格与长期服务、质量、数据安全和退出成本一起考虑。对关键系统或长期合同，提前确认供应商人员变更和分包安排，减少后续管理风险。

本规范适用于提出采购需求、参与比选、签署合同、验收交付和确认付款的员工。办公用品、软件服务、外包项目和涉及系统接入的数据服务可能采用不同流程，但任何采购都应有明确需求、预算、责任人和记录。

需求提出 → 预算确认 → 采购申请 → 询价或比选 → 审批 → 合同签署 → 验收 → 付款与归档。紧急采购也应补充完整记录，不得长期以紧急为由绕过流程。

## 3. 供应商要求

为便于落地，相关人员应明确谁提出、谁审批、谁执行、谁复核以及出现问题时找谁。流程运行一段时间后，根据员工反馈和实际异常补充说明，让制度逐步适应真实工作。

采购过程中的关键沟通和版本变化应及时记录，尤其是范围、价格、交付、验收和付款条件。记录完整，项目发生延期或争议时才有依据处理。

需求部门负责说明问题、规格、数量和验收标准，采购负责流程和比选，财务负责预算与付款，业务验收人负责确认结果，安全、法务和隐私人员在需要时参与评估。参与评审的人员应主动披露利益关系并按要求回避。

供应商应完成必要的资质、主体、财务、制裁与合规审查。涉及公司数据、系统接入或个人信息的供应商，还应接受信息安全和隐私评估，并签署保密及数据处理条款。

## 4. 利益冲突

采购申请应从业务目标出发，说明供应商需要交付什么、何时交付、如何验收以及失败时如何处理。涉及数据、代码、系统权限和长期服务的采购，还应提前确认保密、数据处理、知识产权、分包和退出安排。

参与评审的员工应主动披露与供应商的亲属、投资、任职或其他利益关系，不得利用职务为特定供应商提供不公平便利。

## 5. 验收与记录

验收应依据合同、订单或需求说明核对数量、质量、服务水平和交付物。采购申请、比选材料、合同、验收单和付款凭证应统一归档。

## 6. 检查清单

- [ ] 需求、预算和验收标准明确
- [ ] 供应商资质已完成审查
- [ ] 利益冲突已披露
- [ ] 合同已完成审批和签署
- [ ] 验收及采购资料已归档

**需求提出说明：**

采购申请应说明要解决的问题、数量、规格、预计使用周期、预算来源、期望交付时间和验收标准。不要直接指定某个供应商而不说明客观理由；如果存在兼容性、连续服务或技术专利等特殊原因，应在申请中写清楚。

**比选与评估：**

询价或比选时应尽量向可比的供应商提供一致的需求信息和截止时间。评估可以综合价格、质量、交付、服务、安全、合规和长期成本，不应只按最低报价决定。评审记录应保留评分依据和未中选原因，避免只留下最终结论。

**合同与变更：**

合同应明确产品或服务范围、价格、付款、交付、验收、保密、知识产权、数据保护、违约和终止条件。需求、数量、价格或交付发生变化时，应走变更审批，不通过私下口头承诺扩大供应商工作范围。

**供应商接入与数据安全：**

供应商需要访问系统、办公区域或公司数据时，应限定账号、时间和权限，并明确联系人和退出方式。项目结束后及时回收访问权限和资料。供应商发生安全事故、人员变更或分包时，应按合同和公司要求通知并重新评估。

**验收与付款：**

验收人应根据订单和合同逐项核对数量、质量、服务结果和问题整改。发现不符合时，应记录差异、责任和处理期限，不在问题未解决时盲目确认完成。付款资料应与采购申请、合同、发票和验收记录能够相互对应。

**常见风险处理：**

- **供应商要求绕过采购流程**：说明公司要求并联系采购负责人，不私自承诺。
- **评审成员与供应商有关系**：立即披露并申请回避，由其他人员接替评审。
- **交付延期**：记录影响和补救方案，必要时启动替代供应商或合同措施。
- **发现供应商数据泄露**：停止继续扩大共享，通知安全、法务或采购负责人。

**落地建议：**

采购需求提出部门应尽早参与验收标准设计，不要把所有判断留给采购或财务。对高频、低风险物品可以建立标准目录，对涉及系统接入、个人信息和长期服务的采购则提前引入安全、法务或隐私人员，减少签约后反复返工。

**员工自查：**

提出采购前确认是否已有可复用资产或合同，明确预算和验收人。接触供应商时保持信息对称、记录关键沟通并主动披露关系；发现交付、价格或数据安全异常时及时升级。

**复盘与改进：**

采购完成后复盘交付质量、沟通成本和供应商风险，必要时更新标准目录、合同条款或评估清单。

采购申请应从业务问题开始，而不是从某个供应商或某个产品名称开始。申请人要说明当前痛点、预期结果、数量、规格、使用周期、交付地点和验收方法。需求越清楚，采购、财务和供应商越容易比较，也越不容易在交付阶段发生争议。

预算确认不只是查看账户余额，还要判断后续维护、实施、培训、续费和退出成本。一次性报价低但长期使用成本高的方案，不一定真正节省费用。涉及多个部门时，应提前确定成本归属、付款节奏和最终验收人，避免采购完成后才争论由谁负责。

供应商比选应尽量提供一致的需求说明、时间窗口和答疑信息。评估可以综合价格、质量、交付能力、服务、信息安全、隐私、许可证和长期成本。评审记录应能说明为什么选择某方案，而不是只留下最低报价或最终合同。

合同签署前确认范围、价格、付款、验收、服务水平、保密、数据处理、知识产权、分包、违约和终止条款。需求变化时重新确认影响和审批，不要通过私聊、口头承诺或供应商临时邮件扩大服务范围。紧急采购也要留下事实、原因和后续补审记录。

供应商接入系统或数据时，应采用实名账号、最小权限和明确期限。项目结束、人员变更、合同终止或供应商转包时，回收访问权限和资料。对个人信息、源代码、财务信息和生产系统，应在采购早期引入安全、隐私或法务人员评估。

验收应按照合同和订单逐项核对数量、质量、服务结果和整改情况。发现问题时记录差异、责任人、补救期限和付款影响，不要为了赶进度直接确认全部完成。采购资料、比选文件、合同、验收单和付款凭证应放在统一位置，方便后续审计和复盘。

高频、低风险采购可以建立标准目录、价格参考和简化流程，但仍要保证需求真实、用途清楚和验收可追溯。标准目录定期复核，发现价格、规格、供应商服务或许可证发生变化时及时更新，避免员工继续使用已经过期的默认选项。

供应商沟通应尽量使用公司渠道并保留关键结论。电话或会议确定的价格、范围、交付和变更，随后用邮件或系统确认。不要把重要承诺只留在个人手机、私人聊天或口头交流中，否则后续验收和争议处理都缺少依据。

供应商人员访问办公区或系统时，应有明确的陪同、登记和权限回收安排。外包人员更换时重新确认其账号、设备和数据权限，不要因为合同主体没有变化就默认原人员仍可访问。发现供应商使用未经批准的分包或工具时，及时通知采购和安全负责人。

评审过程中应给予可比供应商合理、完整、一致的信息，不通过内部关系提前透露竞争性报价或评分标准。与供应商存在亲属、投资、兼职或其他利益关系的人员主动回避，避免让团队在事后解释为什么某一方案被特殊对待。

供应商出现延期、质量不达标、服务中断或安全事件时，先确认业务影响和临时方案，再依据合同处理。不要为了维持关系而跳过记录，也不要由单个员工私自承诺豁免。项目结束后总结实际成本、问题和合作经验，帮助下一次采购减少重复风险。

采购流程的价值在于让需求、决策和交付能够被复核，也让业务人员不必独自承担供应商选择和合同风险。业务、采购、财务、安全和法务应在需要时尽早参与，职责分清后再推进。对简单事项保持流程简洁，对高风险事项保持足够的评估和记录。

流程完成后，参与人员应能够回答需求为什么产生、为什么选择该供应商、交付是否符合标准、付款是否有依据以及后续风险由谁负责。如果这些问题无法从记录中得到答案，就说明采购材料或审批链仍需要改进，而不是简单增加更多签字环节。

把决策依据和交付结果留存下来，能够让后续续约、替换或审计都有可靠依据。
