# 邮件与即时通讯使用规范

> 版本：V1.0｜适用对象：使用公司邮箱、企业微信、Slack、Teams 或其他公司通讯工具的人员。

## 1. 使用原则

在实际工作中，本节内容应作为后续流程的判断基础。员工遇到新情况时，先确认目标、事实和影响，再选择对应的处理方式；管理者应确保相关说明能够被员工找到、理解并执行。

员工在发送第一封重要邮件时，应先确认希望对方完成什么动作，再组织背景和附件。收件人越多，越要避免把不确定的讨论写成确定结论。

邮件和即时通讯是企业日常协作的重要记录渠道，清晰、准确和适度的沟通能够减少误解和重复劳动。员工应根据事项重要性选择合适工具，避免把所有内容都塞进群聊，也避免让关键决策只存在于个人对话中。

公司通讯工具用于工作沟通。员工应保持表达准确、礼貌、简洁，重要事项尽量在正式系统中留痕，避免仅依赖口头或临时消息。

## 2. 邮件要求

具体适用时，应结合岗位、业务场景和风险程度判断，不宜只看表面形式。规则发生变化或现有说明无法覆盖时，及时向指定负责人确认，并把已经确认的处理方式记录下来，避免不同人员重复猜测。

群组和频道应有明确主题、成员范围和文件入口，项目结束后及时清理外部成员和临时权限。大群不应成为所有业务信息的默认存储位置。

本规范适用于公司邮箱、企业微信、Slack、Teams 以及其他批准的通讯工具。对外邮件、内部群组、项目频道和临时会话可以有不同的权限和保存方式，但都应遵守收件人最小化、敏感信息保护和记录可追溯原则。

1. 主题应准确概括事项，正文说明背景、结论、行动项、负责人和截止时间。
2. 回复或转发前核对收件人、抄送范围、附件和链接权限，避免误发和全员滥发。
3. 发送外部邮件时，确认对方身份和业务必要性；涉及敏感信息时使用批准的加密方式。
4. 收到异常催促、索要密码、付款或敏感资料的邮件时，不直接操作，应通过独立渠道核实。

## 3. 即时消息

为便于落地，相关人员应明确谁提出、谁审批、谁执行、谁复核以及出现问题时找谁。流程运行一段时间后，根据员工反馈和实际异常补充说明，让制度逐步适应真实工作。

当消息涉及冲突、敏感资料或重大决策时，文字应尽量客观完整，避免使用容易被误读的讽刺和模糊表达。必要时安排正式会议，并把结论写入记录。

发件人负责确认内容、收件人、附件、链接和授权范围；群主或频道管理员负责成员和文件权限；经理负责建立合理的回复预期和紧急联系机制。任何人发现误发、可疑消息或公开链接，都应及时采取限制和报告措施。

紧急事项应明确标注背景、影响和期望响应时间；非紧急事项避免深夜打扰。群聊应围绕工作主题，不传播未经证实的消息、歧视性内容或与工作无关的敏感材料。

## 4. 记录与保留

正式邮件应包含清晰主题、背景、结论和行动项，即时消息适合快速协调但不应替代合同、审批、客户承诺和生产变更记录。付款、改密、验证码和敏感资料请求应通过独立渠道核实，不要被紧急语气推动操作。

合同、审批、客户承诺、事故处理等关键内容应转存至正式系统。不得依赖个人聊天记录作为唯一业务依据。

## 5. 检查清单

- [ ] 收件人和抄送范围已确认
- [ ] 附件、链接和权限已检查
- [ ] 敏感请求已通过独立渠道核实
- [ ] 关键结论已记录在正式系统

**邮件写作建议：**

复杂事项可以先给结论，再补充背景和细节。行动项最好写成“负责人 + 动作 + 截止时间”的形式，例如“张三在周五前确认接口字段”。需要对方决策时，明确列出选项、推荐方案和不决策的影响，减少来回沟通。

**收件人和附件检查：**

发送前重点检查自动补全出的收件人、外部域名、抄送范围和隐藏收件人。附件应使用正确版本，文件链接应确认访问权限。群发时尽量使用邮件组或密送功能，不把无关人员的邮箱暴露给所有收件人。

**识别可疑消息：**

遇到付款、改账号、重置密码、提供验证码、下载附件或转发客户资料等请求时，先核实身份和业务背景。可疑消息常见特征包括异常域名、语气过度紧急、附件格式异常、要求绕过流程或承诺“不要告诉别人”。不要为了验证而点击未知链接。

**即时通讯中的信息边界：**

即时消息适合快速协调，不适合作为合同、财务审批、客户承诺和生产变更的唯一记录。重要决定应转入项目管理、工单、知识库或邮件。不要在大群里发送完整客户名单、员工健康信息、密码、密钥和未经确认的事故信息。

**常见异常处理：**

- **误发邮件**：立即联系 IT 评估撤回或限制访问，并向经理和数据负责人报告。
- **收到冒充领导的消息**：通过已知电话或正式渠道核实，不按消息中的付款指令操作。
- **群聊信息失控**：停止继续扩散，联系群管理员删除或限制访问，并保留必要证据。
- **重要结论只存在聊天中**：整理成简短纪要，发送给相关人员并存入正式系统。

**工作时间与回复预期：**

团队应明确紧急事项渠道和普通事项回复时间。员工休假、出差或非工作时间可以设置自动回复和状态提示。不要通过深夜连续发送消息制造紧迫感；真正紧急的事项应说明影响、需要的动作和最晚响应时间。

**落地建议：**

部门可以统一几个常用模板，例如项目决策邮件、故障通报、会议纪要和外部资料发送说明。模板不应限制员工表达，而是帮助大家遗漏更少的背景、负责人和截止时间。定期清理无效群组、过期机器人和公开链接，也能降低消息噪音和误发风险。

**员工自查：**

发送前核对收件人、附件和链接权限；处理付款、密码或敏感资料请求时通过独立渠道确认。重要决定不要只留在即时消息中，及时整理到正式记录位置，并在休假时设置清晰的状态说明。

**复盘与改进：**

若团队频繁出现误发、遗漏或消息噪音，应调整群组、模板和归档方式，而不是单纯要求员工增加阅读时间。

工作邮件和即时消息都应让接收人能够快速理解背景、结论和下一步动作。复杂事项可以先给结论，再补充事实、选项和风险；需要对方决策时写清截止时间和不决策的影响。行动项最好包含负责人、动作、截止日期和交付位置，避免只写“请跟进”。

发送前应特别检查自动补全出的收件人、外部域名、抄送范围、附件版本和链接权限。涉及客户、薪酬、财务、源码或个人信息时，确认收件人确实有必要知道。外发文件应尽量使用受控链接和有效期，而不是把永久副本散落在多个邮箱中。

付款、改账号、重置密码、提供验证码、下载附件和绕过审批等请求，即使来自熟悉的人，也应通过独立渠道确认。异常消息常常使用紧迫语气、相似域名或“不要告诉别人”的要求。怀疑是钓鱼消息时，不要点击链接或回复原邮件，可通过正式安全渠道上报。

即时通讯适合快速协调，但不适合作为合同、客户承诺、财务审批、生产变更和事故结论的唯一记录。重要内容应整理到项目系统、工单、知识库或正式邮件。群聊中不要发送完整客户名单、密码、密钥、员工隐私或未经确认的事故信息。

团队可以约定普通事项、重要事项和紧急事项的回复时间及渠道。员工休假、出差或专注工作时更新状态，减少别人反复追问。真正紧急的消息要说明影响和希望对方采取的动作，不要只发送“尽快联系我”来制造不必要的紧张。

外部沟通要确认代表身份和授权范围。没有授权时不要对价格、交付时间、产品路线、赔偿或安全事件作出承诺。发现误发邮件、群聊误分享或链接权限过宽时，立即撤回或限制访问并报告，不要因为消息已经发送就放弃处理。

邮件线程较长时，可以定期整理当前结论、未决问题和下一步，避免新的参与者需要阅读几十封历史邮件才能理解背景。转发内容时删除无关的内部讨论和个人信息，确认被转发的附件和链接仍适合新的收件人查看。

即时消息中的表情、缩写和简短回复容易被不同的人理解成不同语气。涉及冲突、客户承诺、绩效反馈和重要决策时，尽量使用完整句子和清晰结论。对方没有回复时，不要连续发送大量催促消息，应说明影响和最晚需要响应的时间。

群组和通讯录应由明确人员维护，项目结束后关闭临时群或更新群说明。将不再需要的机器人、公开链接和外部成员清理掉，减少误发和过期信息继续扩散的机会。重要群组最好设置管理员和基本的文件共享规则。

发送外部资料前，可以让同事进行快速复核，尤其是客户名单、报价、合同、财务表和产品路线图。复核重点是收件人、版本、敏感信息和是否存在未经授权的承诺。必要时使用批准的模板和加密方式，不要把安全责任完全交给接收方。

邮件和聊天记录不应无限制保存所有内容，也不应在争议发生时随意删除关键记录。员工应遵守公司的保留、归档和删除要求。需要留存的合同、审批、故障和决策信息，应转移到相应的正式系统，便于后续查找。

良好的沟通习惯会直接影响协作速度。清晰的主题、合适的受众、明确的行动项和可靠的记录入口，可以减少重复询问和错误执行。团队应根据实际工作不断调整模板和群组规则，让沟通工具支持业务，而不是让员工花更多时间寻找消息。

沟通规则也需要给员工保留合理的专注和休息时间。非紧急事项不要求立即回复，发起人应尽量一次提供完整背景和所需动作。这样不仅减少消息往返，也能让接收人更准确地判断优先级和安排工作。

沟通工具越清晰可控，员工越能把时间用于解决问题，而不是反复确认消息和权限。
