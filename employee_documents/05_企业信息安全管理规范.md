# 企业信息安全管理规范

> 版本：V1.0｜适用对象：全体员工、实习生、外包人员和接触公司信息的第三方。

## 1. 目的

在实际工作中，本节内容应作为后续流程的判断基础。员工遇到新情况时，先确认目标、事实和影响，再选择对应的处理方式；管理者应确保相关说明能够被员工找到、理解并执行。

安全要求应覆盖信息产生、使用、传输、保存和销毁的完整过程。员工不能只关注发送环节，而忽略文件下载、打印、临时缓存和项目结束后的副本清理。

信息安全的目标是保护公司业务、客户、员工和合作伙伴的信息，保证系统和数据能够被正确的人在正确的时间使用。安全要求并不只针对技术人员，任何接触账号、文件、设备或客户资料的员工都可能成为风险控制的重要环节。

保护公司信息的机密性、完整性和可用性，降低账号滥用、数据泄露、恶意软件和误操作风险。

## 2. 信息安全基本要求

具体适用时，应结合岗位、业务场景和风险程度判断，不宜只看表面形式。规则发生变化或现有说明无法覆盖时，及时向指定负责人确认，并把已经确认的处理方式记录下来，避免不同人员重复猜测。

经理应确保团队知道哪些系统是批准入口、哪些数据需要脱敏、发生问题找谁。新项目、新供应商和新工具上线前，提前做基本的安全确认通常比上线后补漏洞更有效。

本规范适用于全体员工、实习生、外包人员和第三方协作人员。公开、内部、机密和高度敏感信息应根据风险采用不同的访问、存储、传输和删除方式。无法判断信息级别时，应暂按较高风险处理并向数据或安全负责人咨询。

1. 仅访问完成工作所必需的系统和数据，不越权浏览、复制或导出信息。
2. 账号、令牌、密钥和验证码不得共享、转发或记录在公开位置。
3. 公司文件应存储在批准的系统中，禁止使用个人网盘、个人邮箱和未授权协作工具传输。
4. 离开工位时锁定屏幕，使用公共场所时避免展示敏感信息。
5. 不点击来源不明的链接或附件，不绕过安全软件、网络策略和设备管理措施。
6. 发现钓鱼邮件、异常登录、设备丢失或文件误发，应立即报告，不得自行删除证据。

## 3. 事件报告

为便于落地，相关人员应明确谁提出、谁审批、谁执行、谁复核以及出现问题时找谁。流程运行一段时间后，根据员工反馈和实际异常补充说明，让制度逐步适应真实工作。

安全事件的影响可能随着时间扩大，因此报告速度很重要。员工即使只能提供初步事实，也应先走报告渠道，后续由安全团队补充调查，不必等待自己完全判断原因。

员工负责遵守最小权限、凭证保护、设备安全和事件报告要求；经理负责确保团队有合理的安全流程和培训；IT 与安全团队负责技术控制、监测、响应和改进。安全责任不能因为文件由其他部门保存、系统由供应商提供而被转移。

报告内容至少包括发生时间、涉及系统、异常现象、可能影响和已采取措施。安全团队将根据事件等级进行隔离、调查、恢复和复盘。

## 4. 违规处理

信息安全操作应融入日常工作：打开链接前验证来源，发送文件前检查收件人，离开设备前锁屏，完成任务后回收临时权限。遇到误发、异常登录、设备丢失、恶意软件或可疑请求时，先停止扩大影响，再按紧急渠道报告并保留证据。

故意绕过安全控制、泄露敏感信息或隐瞒安全事件的行为，将按照公司纪律和适用法律处理。

## 5. 检查清单

- [ ] 只访问与岗位相关的数据
- [ ] 敏感信息存放于批准系统
- [ ] 设备离开时已锁屏
- [ ] 可疑邮件未点击并已报告
- [ ] 安全事件已保留证据并及时上报

**日常安全操作：**

员工每天开始工作时，应确认设备、账号和网络状态正常；结束工作或离开工位时锁屏并收好纸质材料。不要把门禁卡、验证码、密钥、客户导出文件和内部截图放在桌面、公共群聊或无关工单中。打印敏感文件后应及时取走，废弃纸张使用指定回收方式处理。

**识别常见风险：**

钓鱼邮件通常会制造紧迫感，要求立即付款、修改密码、打开附件或提供验证码；假冒同事的即时消息可能使用相似头像和语气。遇到异常请求，应通过通讯录中的已知号码、正式工单或当面方式核实，不要直接回复原消息中的联系方式。

**数据和权限使用：**

访问数据前先确认业务目的和权限范围，下载后及时清理本地副本。需要共享时优先使用公司批准的链接，并设置最小权限和有效期限。项目结束、岗位调整或任务完成后，应主动申请收回不再需要的权限。

**安全事件应对流程：**

发现异常后，先停止可能扩大影响的操作，例如断开可疑网络连接、暂停文件共享或冻结账号，但不要擅自删除邮件、日志或设备证据。随后报告事件发生时间、系统、异常现象、涉及人员和已经采取的措施。安全团队可能要求保持设备开机或暂时不要重置密码，员工应按指导配合。

**常见场景示例：**

- **误把文件发给错误收件人**：立即停止后续转发，撤回或限制链接权限并报告。
- **电脑出现勒索提示**：不要支付、不要反复尝试，断开网络并联系 IT/安全团队。
- **收到供应商索要验证码的电话**：拒绝提供，通过正式渠道核实对方身份。
- **发现同事账号异常登录**：提醒其通过正式渠道确认，同时报告安全团队。

**安全文化：**

信息安全不是 IT 部门单独承担的工作。员工不应因为担心被责备而隐瞒误操作，及时报告通常比晚报更容易控制影响。管理者应关注问题根因和流程改进，避免把所有安全问题简单归结为个人粗心。

**落地建议：**

部门可以把高频风险做成短案例，在入职培训、项目启动和季度沟通中重复提醒。安全要求应尽量嵌入工具和流程，例如默认关闭公开链接、定期提醒权限复核、在外发文件前增加确认步骤。员工遇到不确定事项时，优先咨询安全联系人，避免凭经验绕过控制。

**员工自查：**

每天工作结束前检查是否锁屏、关闭公开链接、收好纸质材料和移除不必要的下载文件。收到异常请求或发生误操作时，先保护现场并报告，不要因为担心影响评价而延迟处理。

**复盘与改进：**

安全事件结束后关注流程和工具是否需要改进，例如增加提示、缩小默认权限或优化报告入口，避免只依赖人工记忆。

信息安全要求应当融入每天的工作习惯，而不是只在培训考试或发生事故时出现。员工处理文件、邮件、系统和设备时，都应先确认自己是否有权限、是否确实需要这些数据、是否使用了正确渠道。工作完成后，应及时关闭临时访问、删除不必要副本并清理公开链接。

钓鱼邮件和冒充消息往往利用紧迫感、权威感或熟悉的称呼诱导操作。遇到付款、改密、提供验证码、下载附件、打开远程控制工具等请求时，应通过通讯录中的已知方式独立核实。不要只因为对方知道姓名、部门或项目名称就认定其可信。

员工不应把密码、密钥、访问令牌和恢复码写入代码、截图、普通文本、公开工单或群聊。必要的技术凭证应使用公司批准的密钥管理方式，并明确所有者、轮换周期和回收责任。项目结束后，临时账号和临时共享链接也要一并检查。

当发生误发、丢失、异常登录、恶意软件提示或权限越界时，第一步是停止扩大影响，第二步是保留现场和证据，第三步是报告。不要为了“先恢复正常”而格式化设备、删除日志或反复尝试登录。安全团队需要准确知道发生了什么，才能判断影响范围和补救措施。

部门负责人应定期检查高风险工作是否有替代流程，例如关键岗位离岗时如何交接、系统不可用时如何继续服务、客户数据如何脱敏。安全控制如果过于复杂导致员工频繁绕过，管理者和安全团队应共同改进流程，而不是只增加惩罚。

培训可以采用短案例、模拟钓鱼和真实问题复盘，但不要让员工担心“报告错误就会被责备”。及时报告通常能够缩小损失，也能帮助组织发现工具和制度上的缺口。每次事件结束后，应把可公开的经验沉淀到知识库和新员工材料中。

员工处理敏感资料时，应先确认资料来源和使用目的，再决定是否下载、复制、打印或转发。工作完成后只保留必要版本，避免桌面、下载目录和个人聊天中堆积大量临时文件。文件名称、压缩包和截图也不能成为绕过权限控制的方式。

管理者应关注团队的实际工作压力。如果安全流程要求过多、审批时间过长或工具经常不可用，员工可能会寻找非正式替代方案。安全团队可以通过自动化、默认安全配置和更清晰的例外流程降低摩擦，让合规成为最省力的选择。

第三方和外包人员接触公司信息时，必须明确其身份、工作范围、账号期限和数据边界。不要因为对方长期合作或由熟人介绍就跳过权限、保密和安全评估。项目结束后确认资料、设备、账号和共享链接均已回收。

安全事件报告应避免使用模糊结论，例如“好像被黑了”。更有帮助的信息是何时看到异常、使用了什么设备、点击了什么内容、哪些文件可能被访问、是否通知过其他人。准确的事实能让调查人员更快隔离风险，也能减少不必要的扩大处理。

公司可以定期检查员工是否仍能找到安全联系人、报告入口和应急说明。岗位变化、系统迁移和办公地点变化后，应重新确认这些信息。安全制度只有在真正发生问题时能够被快速找到和执行，才算完成了落地。

安全管理还应尽量做到分层提醒：普通员工掌握账号、文件和邮件的基本操作，开发和运维人员额外关注密钥、日志和生产权限，管理者关注授权、事件升级和业务连续性。这样既能避免所有人面对同样的复杂要求，也能把高风险岗位的责任说清楚。

在安全要求发生变化时，应告诉员工变化原因、影响范围和需要采取的动作，并提供足够的迁移时间。只发布一句“立即遵守新规则”容易导致误解和绕行。通过示例、常见问题和服务台支持，可以让制度变化更快转化为稳定的日常行为。

安全意识只有进入日常选择和操作细节，才能真正降低误操作与外部攻击造成的影响。
