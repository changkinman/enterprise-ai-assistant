# 客户与外部来访接待规范

> 版本：V1.0｜适用对象：接待客户、供应商、候选人、媒体或其他外部访客的员工。

## 1. 接待准备

在实际工作中，本节内容应作为后续流程的判断基础。员工遇到新情况时，先确认目标、事实和影响，再选择对应的处理方式；管理者应确保相关说明能够被员工找到、理解并执行。

接待前确认访客身份和目的，也要确认哪些内容可以说、哪些内容需要业务负责人批准。准备工作越清楚，现场越不容易因为临时请求而暴露不应公开的信息。

接待工作直接影响客户体验、公司形象和信息安全。一次合格的接待不仅是安排会议室，还包括确认访客身份、控制访问范围、准备合适资料、安排授权人员和完成会后跟进。

提前确认访客身份、来访目的、时间、人数、联系人、会议室和所需设备。涉及敏感区域、系统演示或资料查看时，应事先完成审批和访问范围设计。

## 2. 现场管理

具体适用时，应结合岗位、业务场景和风险程度判断，不宜只看表面形式。规则发生变化或现有说明无法覆盖时，及时向指定负责人确认，并把已经确认的处理方式记录下来，避免不同人员重复猜测。

现场接待时应保持礼貌，但礼貌不等于无条件满足请求。访客要求进入受限区域、拍摄、下载资料或连接设备时，先说明需要确认并联系授权人员。

本规范适用于客户、供应商、候选人、媒体、合作伙伴和其他外部访客。普通拜访、敏感项目交流、系统演示和需要进入受限区域的访问可以采用不同安排，但都应遵守登记、陪同、授权和信息保护要求。

访客进入办公场所应按要求登记并佩戴访客标识，由公司人员陪同，不得自行进入办公区、机房、档案室或其他受限区域。会后及时归还门禁卡和临时设备。

## 3. 信息披露

为便于落地，相关人员应明确谁提出、谁审批、谁执行、谁复核以及出现问题时找谁。流程运行一段时间后，根据员工反馈和实际异常补充说明，让制度逐步适应真实工作。

会后应及时整理客户问题、内部行动项和待确认承诺。所有外部回复都应由合适的业务负责人发出，避免不同人员向客户提供互相矛盾的说法。

接待人负责确认日程、访客、材料和现场安排，行政或前台负责登记和门禁，业务负责人负责对外承诺，IT、安全和隐私人员在涉及系统或敏感数据时参与。任何人都不能仅凭熟悉关系让访客绕过登记或权限。

对外介绍公司、产品、客户、价格、路线图和经营数据时，应使用批准材料，不承诺未经授权的价格、交付时间或合作条款。演示环境应使用脱敏或模拟数据。

## 4. 礼品与费用

会前准备公开或批准材料、模拟账号和备用方案，避免使用真实生产数据和未授权截图。现场发现访客要求拍摄、进入受限区域、获取额外资料或提出价格承诺时，先确认权限和负责人，不要为了现场顺利而直接答应。

接待费用、餐饮、礼品和交通安排应符合预算及反商业贿赂要求。涉及异常高价值礼品、现金或个人利益时，应拒绝并向合规联系人咨询。

## 5. 检查清单

- [ ] 来访身份和目的已确认
- [ ] 访客已登记并由员工陪同
- [ ] 访问区域和系统权限已限制
- [ ] 演示资料不含真实敏感数据
- [ ] 对外承诺已获得授权

**接待前确认：**

接待人应提前了解访客身份、公司、职位、来访目的和是否涉及保密事项。需要多个部门参与时，明确主接待人和各自职责。客户会议应准备经过批准的介绍材料、演示账号和备用方案，不直接使用包含真实生产数据的后台页面。

**到访与现场安排：**

前台或指定人员核验访客信息后发放临时标识，接待人应按约定时间到场。访客临时增加人员、要求进入受限区域或携带拍摄设备时，应先确认是否允许。会议室白板、打印材料和屏幕内容在会后及时清理。

**信息披露边界：**

员工可以介绍已公开或已批准的公司、产品和服务信息，但不应推测未公开的财务、客户、人员、路线图和安全细节。客户提出技术、价格、合同或交付承诺时，应记录问题并转给有授权的负责人，不为了现场气氛而随口答应。

**演示与资料发送：**

演示前检查账号权限、数据脱敏、网络连接和录屏设置。会后发送资料前确认收件人、文件版本、访问期限和保密要求；未经过批准的内部文件不因客户提出请求就直接发送。若客户要求提供样例数据，应使用模拟数据或经过脱敏的数据。

**礼品、餐饮和交通：**

安排餐饮、礼品和交通时，说明业务目的、参与人员和预算。不要用高价值礼品、现金或私人转账换取业务机会或特殊待遇。访客提出超出公司政策的要求时，应礼貌说明限制并请业务负责人或合规联系人处理。

**异常场景：**

- **访客提前到达**：由前台或行政联系接待人，不让访客自行进入办公区。
- **访客要求拍摄**：确认拍摄范围，避开员工屏幕、白板、门禁和敏感区域。
- **访客遗失物品或发生受伤**：协助联系行政和必要的应急服务，并记录事实。
- **访客试图访问未授权系统**：立即停止演示或收回设备，不与其争论，通知负责人。

**落地建议：**

常规接待可以准备标准日程、访客登记说明、演示环境和资料发送模板；重要客户或高敏感来访则单独做风险评估。接待结束后由主联系人确认门禁、账号、资料和后续事项已关闭，避免访客离开后仍保留临时权限或公开链接。

**员工自查：**

接待前确认来访目的和授权范围，现场不展示无关资料，发送文件前复核版本和收件人。接待结束时清理白板、临时账号和公开链接，并把待办事项交给明确的业务负责人。

**复盘与改进：**

重要接待结束后记录客户关切、内部待办和现场风险，完善下次使用的材料、演示环境与访问安排。

必要时将经验同步给前台、行政和业务团队。

接待准备应从访客目的和风险开始，而不是只准备会议室和茶水。提前确认访客身份、公司、职位、人数、到访时间、主要议题和是否涉及保密内容。需要多个部门参与时，确定主接待人、备用联系人和会议结束后的跟进负责人。

访客到达后按要求登记、核验并佩戴临时标识，由公司人员陪同进入办公区域。访客临时增加人员、要求拍摄、进入机房或查看其他系统时，应先确认权限。前台和接待人之间要有清晰的通知方式，不能让访客在无人陪同的情况下自行寻找办公区域。

演示和资料准备应使用经过批准的环境。真实客户数据、生产后台、员工信息、未公开经营数据和内部安全配置不应直接展示。若需要展示效果，优先使用模拟账号、脱敏数据和预设场景；演示前检查账号有效期、共享屏幕范围、录屏设置和网络备用方案。

员工可以介绍公开或已批准的信息，但不能为了现场气氛随口承诺价格、交付时间、产品路线、赔偿或技术能力。客户提出超出授权范围的问题时，记录原问题和背景，承诺由相应负责人回复，而不是用推测性答案代替正式结论。

礼品、餐饮、交通和活动安排应说明业务目的、参与人员、预算和审批情况。现金、购物卡、高价值个人礼品和明显影响决策的招待不得通过“客户习惯”或“行业惯例”规避。无法判断时先咨询合规或业务负责人，避免接收后才被动处理。

接待结束后清理白板、纸质文件、临时账号、访客门禁和共享链接，确认客户资料发送给正确联系人。若发生误发、设备遗失、访客受伤、越权访问或现场争议，立即通知行政、安全和业务负责人，记录事实而不是只凭口头回忆。

接待日程应给不同环节留出缓冲，例如签到、门禁、设备调试、会议切换和资料确认。客户迟到、提前到达或临时改变议题时，接待人可以调整顺序，但要保护受限区域和敏感资料，不因为时间紧张就跳过登记和权限确认。

会议室和演示设备使用前检查屏幕共享、麦克风、录屏、浏览器标签和通知弹窗。一个不经意的桌面窗口可能暴露客户、员工或系统信息。演示结束后关闭会话、清理缓存和临时文件，避免下一个使用者看到上一场会议内容。

客户提出资料、样例、日志或系统截图请求时，应确认用途、范围、格式和发送权限。可以提供公开资料或经过批准的脱敏样例，但不要直接从生产环境截图或导出。需要业务负责人、法务、安全或隐私审核时，明确告诉客户回复时间和负责联系人。

接待中的餐饮、礼品和交通安排应保持适度、透明和与业务有关。不能用私人支付、个人账户转账或第三方代付方式隐藏实际费用。员工不确定某项安排是否合规时，应提前咨询；越早咨询，越容易设计出符合双方需要的替代方案。

接待结束后的跟进应区分客户承诺、内部行动项和待确认问题。将会议结论发给参与者，明确谁在何时回复，避免客户认为现场口头讨论已经成为正式承诺。对于重要客户，可以安排专人跟进资料、试用账号和后续会议权限。

接待质量不只体现在现场是否顺利，也体现在客户离开后资料、权限和承诺是否被正确处理。业务负责人应在会后检查行动项，相关部门按授权完成回复，行政和 IT 确认临时资源已关闭。对重复出现的接待问题，可以更新标准材料和培训说明，减少每次临时准备。

对于高频客户接待，可以把常用信息、演示流程和风险提醒整理成内部操作包，但每次使用前仍要确认资料版本、访客范围和业务授权。标准化是为了减少遗漏，不是为了让接待人跳过针对具体客户和具体会议的判断。

接待过程中的任何临时决定都应考虑后续影响，例如临时开通账号是否会自动延长、临时发送的链接是否公开、临时拍摄是否包含其他客户或员工信息。主接待人可以在会议结束前做一次快速收尾确认，把资料、权限、费用和行动项逐项交给明确负责人，避免现场顺利但事后留下隐患。

专业接待不仅体现在现场表现，也体现在资料、权限、承诺和后续行动都得到妥善处理。
