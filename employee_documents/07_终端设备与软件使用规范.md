# 终端设备与软件使用规范

> 版本：V1.0｜适用对象：使用公司电脑、移动设备、服务器或软件资源的人员。

## 1. 设备管理

在实际工作中，本节内容应作为后续流程的判断基础。员工遇到新情况时，先确认目标、事实和影响，再选择对应的处理方式；管理者应确保相关说明能够被员工找到、理解并执行。

领用设备时应确认设备适合岗位工作，例如是否需要开发环境、加密存储、特殊网络或移动办公能力。配置不匹配时及时提出，比员工自行安装未经批准的软件更安全。

终端设备是访问公司系统和处理业务数据的重要入口，设备状态直接影响工作效率和信息安全。公司设备应主要用于工作，员工需要在安全、合理和不影响业务的范围内使用，并对领用设备和配件承担保管责任。

公司设备用于工作目的。员工应妥善保管设备，不得擅自拆机、刷机、关闭安全策略或将设备交给无关人员使用。设备离开公司或办公场所时，应采取防盗和加密措施。

## 2. 软件安装

具体适用时，应结合岗位、业务场景和风险程度判断，不宜只看表面形式。规则发生变化或现有说明无法覆盖时，及时向指定负责人确认，并把已经确认的处理方式记录下来，避免不同人员重复猜测。

软件和补丁管理应有清晰的责任人和时间窗口。员工收到更新提示时应配合完成，遇到业务冲突则反馈具体影响，由 IT 安排例外，而不是长期忽略更新。

本规范适用于电脑、手机、平板、服务器、测试机、移动存储和公司批准的软件。个人设备如果被批准用于工作，也应遵守数据、账号和远程访问要求。涉及生产系统、客户资料或源代码的岗位，应根据风险设置更严格的终端控制。

1. 仅安装公司批准的软件和浏览器扩展，必要时通过 IT 服务台申请。
2. 不使用盗版、破解或来源不明的软件，不下载绕过授权或安全控制的工具。
3. 开发人员引入开源组件时，应遵守公司许可证和供应链安全要求。
4. 收到系统更新和安全补丁提示时，应在规定时间内完成安装并重启设备。

## 3. 数据处理

为便于落地，相关人员应明确谁提出、谁审批、谁执行、谁复核以及出现问题时找谁。流程运行一段时间后，根据员工反馈和实际异常补充说明，让制度逐步适应真实工作。

设备维修或借用期间，应确认数据如何迁移、临时账号如何使用以及归还后如何清理。设备交接应由双方确认状态，避免因缺少记录导致资料丢失或资产责任争议。

员工负责设备保管、锁屏、更新、软件合规和异常报告；IT 负责标准配置、补丁、维修、远程保护和报废处置；经理负责确认设备和软件满足岗位需要。设备转交、维修、借用和报废都应有记录，避免数据和资产责任不清。

重要文件应保存在公司批准的存储位置并遵循备份要求。不得将公司数据用于私人项目，不得将生产数据复制到个人设备或未经批准的测试环境。

## 4. 故障与丢失

软件安装前应确认来源、许可证、用途和数据风险，补丁发布后在规定窗口完成更新。员工不得安装破解、盗版、恶意或绕过安全控制的软件，也不得将真实生产数据复制到未批准的开发和测试环境。

设备故障、丢失、被盗、感染恶意软件或出现异常弹窗时，立即断开风险连接并联系 IT；未经指导不得反复尝试、格式化或删除日志。

## 5. 检查清单

- [ ] 设备已设置锁屏和加密
- [ ] 软件来源和许可证合规
- [ ] 系统补丁已及时安装
- [ ] 公司数据未存放在个人设备
- [ ] 故障或丢失已向 IT 报告

**设备领用与日常保管：**

领用设备时确认资产编号、配置、外观和配件，发现缺失或损坏应立即记录。员工离开工位时锁屏，离开办公地点时避免把设备放在车辆可见位置。出差携带设备时应使用防护包，不把电脑交给陌生人代管或维修。

**软件安装与更新流程：**

需要新软件时，先确认已有工具是否能够满足需求，再通过 IT 或软件目录申请。申请应说明用途、使用人、数据类型和是否需要管理员权限。安装前检查来源和许可证，安装后及时更新并删除不再使用的插件，尤其是浏览器扩展和远程控制工具。

**移动存储与外设：**

U 盘、移动硬盘、手机和个人电脑都可能造成数据外泄。复制公司数据到移动介质前应确认必要性、加密和审批要求。来源不明的 U 盘、充电设备和线缆不要直接连接公司电脑，发现异常弹窗或系统变慢时应停止操作并联系 IT。

**开发和测试环境：**

开发人员不得把生产密码、客户数据或真实个人信息直接放入本地配置、测试脚本和示例代码。测试数据应脱敏或模拟，临时调试文件应在任务结束后清理。使用开源软件、代码生成工具或第三方服务时，应遵守许可证、保密和供应链要求。

**故障、丢失和报废：**

- **系统异常**：记录错误信息、时间和最近变更，不要连续重装或删除日志。
- **设备丢失**：立即报告设备编号、地点、最后使用时间和可能暴露的数据。
- **疑似中毒**：停止登录其他系统，按 IT 指导隔离设备。
- **设备报废**：由 IT 按照数据清除和资产处置流程处理，员工不得自行出售或拆解。

**使用边界：**

公司设备不应被用于违法、侵权、赌博、挖矿、未经授权的商业活动或影响公司网络稳定的行为。合理的个人使用应以不影响工作、不安装高风险软件和不处理公司敏感数据为前提。

**落地建议：**

部门可在设备领用、转岗和离职节点使用同一份资产清单，减少遗漏。员工发现设备配置不合理、软件重复或补丁经常失败时，应提交改进建议。IT 则应把常见问题、批准软件和升级窗口说明清楚，让员工知道什么时候可以自行处理，什么时候必须报修。

**员工自查：**

定期检查设备是否安装最新补丁、启用锁屏和加密，清理不用的软件及浏览器扩展。出差、转岗和离职前确认设备、配件、文件和临时账号都能按清单交接。

**复盘与改进：**

IT 可根据重复故障和设备维修记录调整标准配置、软件目录和培训内容，减少员工自行寻找高风险替代工具的情况。

设备领用时应核对资产编号、外观、配件和预装软件，发现异常及时记录。日常使用中不要把公司电脑交给无关人员，也不要让家人或访客代为操作。短时间离开工位锁屏，离开办公地点时注意防盗，公共场所不要把设备放在容易被看到或拿走的位置。

软件安装前先确认公司目录中是否已有可用工具。新增软件应说明用途、使用人、需要处理的数据和是否需要管理员权限，来源不明、破解、盗版或会绕过安全策略的工具不得安装。浏览器扩展、远程控制软件和命令行工具也应纳入同样的审查范围。

系统补丁和安全更新通常需要重启或短暂中断工作，员工应在允许的窗口完成，不要长期点击忽略。若更新失败、设备反复重启、磁盘空间不足或出现异常弹窗，应记录现象并向 IT 报修，不要随意关闭安全软件或下载所谓的修复程序。

移动硬盘、U 盘、手机和个人电脑都可能成为数据外泄渠道。复制公司数据前确认是否必要、是否需要加密、是否获得批准，任务结束后删除临时副本。来源不明的外设不要直接连接公司设备，发现系统异常时立即停止操作并报告。

开发和测试人员尤其要避免把生产密码、客户资料和真实个人信息写入本地配置、日志、示例代码或截图。测试环境应使用脱敏或模拟数据，临时调试文件在任务结束后清理。引入开源组件和第三方服务时，还要确认许可证、版本来源和供应链风险。

设备丢失、被盗、感染恶意软件或出现无法解释的异常时，先联系 IT，不要自行格式化。报废设备必须由授权人员完成数据清除和资产处置，员工不能私自出售、拆解或带走。设备生命周期中的每次转移都应留下可追溯记录。

设备性能问题应尽量用事实描述，例如启动时间变长、某个软件频繁崩溃、网络连接反复中断或存储空间不足。不要为了“让它快一点”安装未经批准的优化工具、清理工具或远程控制软件。IT 需要根据现象和日志判断根因，反复自行修改配置可能使问题更难定位。

外出办公时，设备不要长时间留在汽车、行李寄存处或无人值守的会议室。使用公共 Wi-Fi 时遵守公司网络要求，不在屏幕可被旁人看到的地方处理客户名单、薪酬和安全事件。设备离开公司前确认磁盘加密、锁屏和远程保护功能正常。

软件许可证和开源组件也属于设备治理的一部分。安装前确认使用权、版本和更新来源，项目交付前检查是否存在违反许可证或公司政策的组件。员工发现软件即将停止支持、存在严重漏洞或无法安全更新时，应及时通知 IT 或项目负责人。

共享设备、会议室电脑和测试机使用后，应退出个人账号并删除不必要的临时文件。不要在公共设备上保存浏览器密码、访问令牌和个人文件。设备交接时由双方确认数据、账号、配件和资产状态，避免后续出现责任不清。

IT 可以根据维修、丢失、补丁失败和软件申请数据更新标准配置与培训内容。员工也应反馈实际使用中的困难，例如某个安全策略影响工作、批准软件无法满足需求或设备配置不适合岗位。及时反馈有助于在风险可控的情况下改进标准。

设备管理的最终目标是让员工能够稳定、安全地完成工作。公司应在安全、成本、性能和使用体验之间取得平衡，员工则应遵守批准的使用边界并及时报告异常。双方共同维护清晰的领用、更新、维修、交接和报废记录，才能减少设备问题对业务的影响。

设备问题也可以作为流程改进的信号。如果多个岗位反复遇到同一软件缺失、补丁失败或配置不匹配，管理者应与 IT 一起判断是否需要统一解决，而不是让每个人单独寻找办法。统一解决通常更安全，也更节省维护时间。

设备治理应服务于稳定工作，同时让风险发现、报修和回收都能被及时处理。
